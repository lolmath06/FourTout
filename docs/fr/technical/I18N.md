## En résumé

- 16 langues, toutes **embarquées** dans l'application : aucune traduction en
  ligne, aucun téléchargement.
- Le texte source de l'interface est écrit **en français, dans le code** :
  `t("Fichier illisible.")`. Les traductions le retrouvent par une empreinte
  stable de ce texte.
- Les outils ne sont **jamais dupliqués** par langue : `ToolDefinition` reste
  unique ; ses textes traduits vivent à part, indexés par identifiant d'outil.
- Repli : **langue affichée → anglais → texte source**. Une clé brute
  n'apparaît jamais.
- Aucune dépendance ajoutée : le format des messages (sous-ensemble d'ICU) et
  l'exécution tiennent dans `src/i18n/`, la mise en forme passe par `Intl`.

## Où vivent les textes

```
src/i18n/
  locales.ts          langues, rapprochement avec la langue du système
  format.ts           format des messages (ICU réduit), empreinte des messages
  runtime.ts          langue active, chargement, t(), tx(), msg(), localized()
  Trans.tsx           messages balisés (<0>…</0>) rendus en React
  intl.ts             nombres, dates, durées relatives, tailles, tri
  native.ts           reconnaissance des messages du socle Rust
  native.json         gabarits extraits du code Rust (généré)
  messages/
    fr.json           catalogue source : empreinte → texte (généré)
    en.json …         traductions de l'interface, une par langue
  catalog/
    en.json …         noms, descriptions, mots-clés des outils et catégories
scripts/i18n/
  extract.mjs         régénère fr.json et native.json depuis le code
  status.mjs          couverture par langue, catalogue périmé
```

Seul l'anglais est chargé au démarrage (c'est le repli) ; les autres langues
sont des modules séparés, analysés à la demande par `loadLocale()`.

## Écrire un message

```tsx
import { t, msg, tx, localized, Trans } from "@/i18n";

t("Fichier illisible.");                                   // texte simple
t("Page {page}", { page: 3 });                             // variable
t("{count} {count, plural, one {fichier} other {fichiers}}", { count });
<Trans source="Écrit dans <0>{output}</0>" values={{ output }} components={[<code />]} />;
```

- **Variables** `{nom}` : la valeur est insérée telle quelle (un port `8080`
  ou une année ne reçoivent pas de séparateur de milliers).
- **Pluriels** `{n, plural, =0 {…} one {…} few {…} many {…} other {…}}` : la
  forme est choisie par `Intl.PluralRules` de la langue affichée, et `#` est
  remplacé par le nombre **mis en forme**. Une traduction peut introduire un
  pluriel absent du texte source (le polonais et le russe le font souvent).
- **Balises numérotées** `<0>…</0>`, `<1/>` : rendues par `<Trans>`, pour
  qu'une phrase contenant du gras ou un lien reste traduisible d'un seul tenant.
- **Constantes de module** (listes d'options, libellés indexés) : écrire
  `const LABELS = localized(() => ({ … t("…") … }))`. La valeur est réévaluée
  à chaque changement de langue, sans toucher aux usages.
- `msg("…")` marque un texte destiné à être traduit plus tard (au rendu) ;
  `tx(valeur)` traduit une valeur qui *peut* être un message connu, un
  message natif ou une donnée (rendue telle quelle).

Le changement de langue remonte l'arbre React (clé de langue sur le routeur) :
tout se redessine immédiatement, sans redémarrage, et l'URL — donc l'outil
ouvert — est conservée.

## Le catalogue des outils

`ToolDefinition` (dans `src/core/tools/catalog/`) garde le texte source et
toute la structure. Les traductions sont dans `src/i18n/catalog/<code>.json` :

```json
{
  "categories": { "pdf": { "name": "PDF", "description": "…", "keywords": ["…"] } },
  "tools": {
    "pdf-compress": {
      "name": "Compress a PDF",
      "description": "…",
      "keywords": ["compress", "shrink", "…"],
      "aliases": ["compress pdf", "…"],
      "note": "…"
    }
  }
}
```

L'interface ne lit jamais `tool.name` directement : elle passe par
`core/tools/localized.ts` (`toolName`, `toolDescription`, `toolNote`,
`categoryName`…). Le repli est **par champ** : un outil ajouté sans traduction
s'affiche en anglais, ou à défaut en français. Identifiants, routes, favoris
et récents ne dépendent jamais de la langue.

Les `keywords` d'une langue sont écrits **dans cette langue**, comme un
utilisateur les taperait (« pdf komprimieren », « 压缩 »), pas traduits mot à
mot ; les noms de formats y restent tels quels.

## Messages du socle natif

Les erreurs et états renvoyés par Rust arrivent comme du texte français déjà
formé (« Lecture impossible : … »). Plutôt que de modifier le socle natif,
`scripts/i18n/native.mjs` extrait ces textes du code Rust en **gabarits**
(`Lecture impossible : {p0}`), écrits dans `native.json` et ajoutés au
catalogue source. À l'affichage, `tx()` reconnaît le gabarit, traduit le
message et ses valeurs (sur deux niveaux d'imbrication au plus). Un texte qui
ne correspond à aucun gabarit est affiché tel quel.

## Langue affichée, repli et persistance

- Préférence `language` dans les paramètres (`useSettings`, stockage local
  existant) : `"system"` par défaut, ou un code de langue.
- **Système** : première langue préférée du système que FourTout sait
  afficher (`navigator.languages`, fourni par la WebView). Rapprochements :
  `fr-CA → fr`, `de-CH → de`, `zh-SG`/`zh-Hans → zh-CN`,
  `zh-HK`/`zh-MO`/`zh-Hant → zh-TW`, `pt-PT → pt-BR` (la variante disponible
  la plus proche), `in → id` ; sinon l'anglais.
- En mode Système, l'événement `languagechange` est suivi.
- La langue est appliquée **avant le premier rendu** (`initLanguage()` dans
  `main.tsx`) : pas d'écran qui change de langue sous les yeux.
- `<html lang>` et `<html dir>` suivent la langue affichée.

## Nombres, dates, tailles

`src/i18n/intl.ts` : `formatNumber`, `formatDecimal`, `formatPercent`,
`formatDate`, `formatDateTime`, `formatRelativeTime`, `compareText`
(`Intl.Collator`), et `formatBinarySize` / `formatDecimalSize` pour les
tailles (`o`, `Kio`, `Mio` en français ; `B`, `KiB`, `MiB` ailleurs).

La **langue** et le **système d'unités** sont deux sujets distincts : afficher
l'interface en anglais ne convertit pas les kilomètres en miles. Les
convertisseurs d'unités gardent leurs propres choix.

## Recherche multilingue

`src/core/tools/search.ts` construit un index **par langue** (mis en cache) :

- textes de la langue affichée à pleins poids ;
- textes anglais et français source à poids réduit — une requête anglaise
  trouve encore son outil en japonais, sans passer devant une correspondance
  dans la langue affichée ;
- normalisation Unicode (casse, accents latins), découpage aux changements
  d'écriture pour le chinois, le japonais et le coréen (« pdf を圧縮 » →
  `pdf`, `を`, `圧縮`), mots vides et mots directionnels de toutes les
  langues (`src/core/tools/searchLanguages.ts`) ;
- classement déterministe, égalités départagées par `Intl.Collator`.

## Ajouter ou modifier un message

1. Écrire le texte français dans le code avec `t()`, `msg()` ou `<Trans>`.
2. `pnpm i18n:extract` — régénère `messages/fr.json` (et `native.json`).
3. Ajouter la traduction anglaise dans `messages/en.json` (obligatoire : le
   test de couverture l'exige), puis les autres langues.
4. `pnpm i18n:status` — vérifie la couverture et l'absence de clés inconnues.

Modifier un texte source change son empreinte : l'ancienne traduction devient
inconnue (le test la signale) et doit être reportée sur la nouvelle clé.

## Ajouter une langue

1. Déclarer la langue dans `LOCALES` (`src/i18n/locales.ts`), avec son nom
   natif, son code `Intl` et son sens d'écriture.
2. Créer `src/i18n/messages/<code>.json` et `src/i18n/catalog/<code>.json`.
3. Ajouter ses mots vides et directionnels dans `searchLanguages.ts`.
4. Ajouter la langue à `EXPECTED_LOCALES` dans `src/i18n/i18n.test.ts`, avec
   une requête de recherche dans sa langue.

## Tests

`src/i18n/i18n.test.ts` vérifie sur les fichiers réellement embarqués :

- les seize langues sont déclarées, se chargent et s'appliquent à `<html>` ;
- le catalogue source est à jour avec le code (`pnpm i18n:extract` oublié) et
  sans collision d'empreinte ;
- l'anglais couvre 100 % des messages ; chaque langue couvre au moins tout
  le **socle de l'interface** (navigation, accueil, recherche, paramètres,
  composants partagés) et ne contient aucune clé inconnue ;
- chaque traduction garde les variables et balises de sa source, est bien
  formée et fournit toutes les formes plurielles de sa langue ;
- 196 outils et 12 catégories traduits dans chaque langue (nom, description,
  mots-clés, note quand l'outil en a une) ; identifiants et routes inchangés ;
- repli langue → anglais → source, jamais de clé brute ;
- persistance du choix et changement immédiat ;
- rapprochement des langues du système ;
- recherche : « compress a pdf », « comprimir un pdf », « pdf komprimieren »,
  « сжать pdf », « pdf を圧縮 », « pdf 압축 », « 压缩 pdf »… ; noms de formats
  dans toutes les langues ; requêtes anglaises depuis d'autres langues ;
  déterminisme.

`src/i18n/runtimeStrings.test.tsx` est l'audit à l'exécution : il enveloppe
chaque message traduit dans des marqueurs (pseudo-langue), rend toutes les
pages et les 196 outils, et échoue si un texte visible n'est pas passé par la
traduction.

## Audit des chaînes codées en dur

L'audit combine le recensement statique (`scripts/i18n/messages.mjs`, appels
non littéraux signalés par `pnpm i18n:extract`) et le rendu en pseudo-langue
ci-dessus. Exceptions légitimes, laissées telles quelles :

- **noms propres et marques** : FourTout, FFmpeg, Piper, whisper.cpp, Tauri,
  noms de logiciels tiers ;
- **standards techniques** : noms de formats et d'algorithmes (PDF, PNG,
  SHA-256, AES-256, UTF-16 LE…), unités SI, raccourcis clavier (`Ctrl`, `Esc`) ;
- **noms des langues** dans le sélecteur : chacun dans sa propre langue ;
- **données de l'utilisateur** : noms de fichiers, contenus, métadonnées lues ;
- **exemples de données** insérés par un bouton « Exemple » dans les outils
  développeur (JSON, URL encodée) : ce sont des données, pas de l'interface ;
- **sorties techniques** dont le format est normé : manifestes `sha256sum`,
  dossier `donnees` et `manifeste.json` des sauvegardes (format de fichier
  stable, documenté dans la note de l'outil).

## Limites connues

- Les messages du socle natif sont reconnus par gabarit : un message Rust
  construit dynamiquement d'une manière non prévue par l'extraction reste
  inchangé.
- Les médias de présentation dépendent de la langue. Le README français utilise
  la démo française ; le README anglais et les autres README localisés utilisent
  la démo anglaise.
- La documentation publique canonique est en anglais et possède un miroir
  français complet sous `docs/fr/`. Les documents racine de contribution et de
  feuille de route suivent la même organisation anglais/français.
